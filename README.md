Most of my time goes into CTF challenges for Securinets: what makes one fair, where it breaks,
and how a player who never read the source still ends up at the flag. I would rather ship a
challenge that teaches one real technique well than one that is hard for the sake of being hard.

---

### Current work

**`fadigattack`**, an intentionally vulnerable Android app with 17 challenges, each mapped to an
OWASP Mobile Top 10 category. Crypto, storage, WebView, pinning, exported components, binary
protections. The app is built to be broken, and a decompiler alone should not be enough to solve it.
*(Source is private for now.)*

**Reverse engineering track**, in [`CTF`](https://github.com/khalilammarr/CTF/tree/main/re-track):
a beginner ladder of Linux and .NET binaries, each teaching one move (patching, unpacking, debugger
bypass), with writeups.

**Malware triage**: case files built from clean-room samples I compile myself. The goal is a
reader who can follow an intrusion from the first artifact to the persistence mechanism, not one
who memorised a family name.

### Also in the toolbox

- Android: jadx, apktool, frida, objection, adb, Waydroid for testing on a Linux box
- Binaries: Ghidra, GDB with pwndbg, capa rules, diaphora for function diffing
- Firmware reading: OP-TEE, TF-A, and TF-M source, for the trust boundary and not the feature list
- Bug bounty: recon and triage workflow, with a habit of killing weak findings before writing them up
